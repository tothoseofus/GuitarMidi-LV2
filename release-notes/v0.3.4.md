# GuitarMidi-LV2 v0.3.4 — SpeexDSP Resampling and MIDI Timing Reliability

This release replaces the previous zita-resampler integration with the BSD-licensed SpeexDSP resampler and adds automated tests for sample-rate conversion and LV2 MIDI event timestamps.

The primary goals are **simpler redistribution and licensing**, **reliable operation at non-native sample rates**, and **preserving the established 48 kHz real-time processing path**.

## What's new since v0.3.3

### SpeexDSP replaces zita-resampler

- Replaced the zita-resampler dependency with **SpeexDSP 1.2.1** for audio hosts running at sample rates other than 48 kHz.
- Statically build only the required SpeexDSP resampler source as part of the plug-in, avoiding a separate runtime SpeexDSP shared-library dependency.
- Include the upstream SpeexDSP BSD licence notice in packaged LV2 bundles (`SPEEXDSP-LICENSE.txt`).
- Removed zita-resampler installation and linkage steps from the ARM64, Windows and Ubuntu build workflows.
- **The native 48 kHz audio path is unchanged:** it bypasses resampling entirely.

### Streaming resampling improvements

- Added an allocation-free streaming conversion helper with a fixed, preallocated output buffer.
- Preserve resampler state between audio callbacks so fractional positions and filter history continue across variable host block sizes.
- Handle independently reported input consumption and output production without assuming a fixed conversion ratio per callback.
- Process converted audio in bounded chunks that respect the filterbank's native 48 kHz window boundaries.
- Guard against a no-progress conversion loop in the real-time audio callback.

### MIDI event timestamp safeguards

- Bound MIDI event timestamps to the valid sample-frame range of the current LV2 audio block.
- Preserve nondecreasing event order when several MIDI messages are emitted in a block.
- Apply the same timestamp constraints to MIDI notes and diagnostic SysEx events.
- Reset timestamp tracking at every LV2 host callback, including bypassed callbacks.

These safeguards **do not** change the asynchronous neural-network inference algorithm or reconstruct the exact original audio onset time.

### Automated tests and packaging

- Added `resampling_regression` to verify 44.1 → 48 kHz and 96 → 48 kHz streaming conversion, including small and irregular host blocks, output consistency, and buffer bounds.
- Added `midi_timestamp_regression` to verify valid, ordered frame timestamps across host block sizes and sample rates.
- Integrated both regression tests into the Windows x64, Ubuntu 24.04 and Ubuntu 26.04 GitHub Actions builds.
- Confirmed that the Linux release binaries do not dynamically depend on zita-resampler and that packaged plug-ins include the SpeexDSP licence notice.

## Validation

- **Windows x64, Ubuntu 24.04 and Ubuntu 26.04:** both automated regression tests passed.
- **piStomp v3 / Raspberry Pi 5:** tested guitar-to-MIDI operation at 48 kHz (native), 44.1 kHz (upsampling) and 96 kHz (downsampling).
- **JACK block sizes:** tested 128 and 256 frames at both 44.1 and 96 kHz.
- **Real-time operation:** no XRUNs were observed during the reported piStomp tests.
- **MIDI behaviour:** piStomp latency-probe recordings showed broadly comparable note detection and timing relative to the previous zita-based build. Some chord detections differed, and asynchronous inference scheduling can introduce block-scale timing variations.

The real-world results are **observations from the tested hardware and passages**, not a guarantee of zero XRUNs or identical detection in all configurations. No general claim of improved algorithmic latency is made for SpeexDSP.

## Compatibility notes

- Existing LV2 URI and bundle identity introduced in v0.3.3 remain unchanged.
- The plug-in continues to target a **48 kHz internal model-processing rate**, converting non-native host rates before inference.
- No changes to the normal 48 kHz inference scheduling, model or MIDI note-detection thresholds are included in this release.
- The SpeexDSP migration removes the **zita-resampler dependency**; it does not change the licensing obligations of other components of GuitarMidi-LV2.
